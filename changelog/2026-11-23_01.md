## Why Care?

We write open specifications for tools we think should exist: a ledger that pays writers for keeping content current, a content farm that runs itself, a scout that watches for startups. Until now they were scattered. Some had pages, nobody could find them, and the ideas we hadn't written up yet were invisible.

Now there's one place to see all of them, at [/vibe-with/specs](/vibe-with/specs), with a section on the homepage. The ideas still in the works show up too. Click one and it tells you it isn't written yet, and thanks you for the interest. That interest is worth knowing about: it tells us which idea to write up next.

And the specs link heavily into the rest of our work, the plans and blueprints in each repo's `context-v/`. Those links used to point at relative file paths that went nowhere on the web. They now open the real document.

## What's New?

- **An Open Specs page** at [/vibe-with/specs](/vibe-with/specs): image cards for every spec, a status pill (Idea, Stub, Draft, Proposed, Iterating), the lede, and filters for status, written up, and in the works.
- **An Open Specs section on the homepage**, after the Projects Showcase, with a See All link.
- **Unwritten ideas as cards that aren't links.** They're dimmed with an "In the works" ribbon. Clicking one shows a toast, "Not yet developed, thanks for showing interest.", and sends a `spec_interest` event to OpenPanel with the spec's slug.
- **Links into our repos resolve.** A link like `../../ai-labs/corpora-builder/context-v/specs/Storage-Seam.md` now opens that doc on the [context-v-corpus site](https://lossless-group.github.io/context-v-corpus/), or on GitHub when the corpus doesn't have it yet.
- **Old URLs of unpublished specs** now redirect to the Open Specs page instead of the Vibe With Us page.

## How it Works

### Showing unpublished specs without publishing them

The site has one rule that keeps unpublished drafts private: `publishedGlob` drops every `publish: false` entry before any page sees it, so a new route can't leak one by forgetting a check. We didn't want to weaken that for one page.

So unpublished specs come in through a second collection, `spec-ideas`, that reads the same folder but:

- keeps only the `publish: false` entries,
- keeps only the fields a card needs (`title`, `lede`, `status`, `tags`, `portrait_image`, `banner_image`),
- and has no route, so no page is ever built from it.

The card renders a published spec as a link and an unpublished one as a button. We checked the built page for sentences from an unpublished spec's body; none appear.

### Turning relative links into real ones

Content lives in its own repo, and specs link to docs in other repos by relative path. On the web those paths resolve to nothing. Every doc copied into the context-v-corpus records where it came from (`source_path`), and the corpus site publishes a sitemap, so the mapping can be exact rather than guessed:

```text
content link ──► strip ../ ──► monorepo path
                                   │
          corpus has a published copy at that source_path,
          and its page is in the corpus sitemap?
              yes ─► lossless-group.github.io/context-v-corpus/corpus/<id>/
              no  ─► github.com/<repo that contains it>/blob/main/<path>
```

A script, `pnpm links:monorepo`, finds every such link in content and writes the answers to `src/config/monorepo-link-map.json`. The map is committed because building it needs the whole monorepo on disk, which deploy builds don't have. A remark plugin, `remark-monorepo-links`, rewrites links from the map in all eight of the site's markdown pipelines and leaves anything not in the map alone.

On its first run: 49 links, 32 to the corpus site and 17 to GitHub. All 34 on the Lasso spec page load.

## Under the Hood

- **Where to configure it:** `src/config/monorepo-links.json` holds the monorepo, content and corpus paths, the corpus site and sitemap URLs, and the GitHub fallback branch.
- **When to re-run the map:** after adding a relative link to content, or after re-collating the corpus. A new link that isn't in the map stays a dead relative path until then.
- **Astro dev in an agent session:** Astro detects agents and starts `astro dev` in the background with a 30-second startup limit, which this site's content sync exceeds. `ASTRO_DEV_BACKGROUND=1 pnpm exec astro dev` runs it directly.
- **Content fixes made along the way** (in the content repo): `Was-There-a-Substack-for-Event-Attendees.md` had Churn's title, lede and body copied in; it now has its own title and lede and is unpublished until it has its own text. Two full specs with no `publish` key now say `publish: true`.
